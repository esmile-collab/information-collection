# 路由注册表

本文件记录当前已知的能力路由。每次任务仍需核验工具是否可用，以及目标站点的当前访问方式。

## 项目路由

1. 用户明确指定的项目或路径优先。
2. 信息直接服务于已有业务或产品项目时，在该项目中交付。
3. 跨项目的工具评估、采集流程和 Skill（技能）在信息-决策中台沉淀。
4. 一次性查询不为了归档新建目录。

## 来源与工具路由

| 信息场景 | 首选路线 | 需要切换路线的情况 |
| --- | --- | --- |
| 时效性强的公开信息 | 网络搜索，再打开官方或一手页面 | 搜索摘要无法支持结论时，进入原页或查找独立来源 |
| 需登录、点击或动态渲染的网页 | Kimi WebBridge（Kimi 浏览器桥）或 browser control（浏览器控制） | 出现人机验证或会话失效时，由用户完成验证后继续 |
| 飞书文档、知识库和云空间 | lark-doc（飞书文档）、lark-wiki（飞书知识库）、lark-drive（飞书云空间） | 认证失效时先验证登录状态，不读取凭证内容 |
| GitHub（代码托管平台）或本地代码库 | GitHub（代码托管平台）工具、本地搜索和源码阅读 | 需要产品视角的系统拆解时，使用 repo-product-breakdown（代码库产品拆解） |
| PDF（便携式文档）、Word（文档）、Excel（电子表格）、PPT（演示文稿） | 对应的 PDF（便携式文档）、documents（文档）、spreadsheets（电子表格）、presentations（演示文稿）Skill（技能） | 视觉版式影响含义时，同时渲染页面并目视复核 |
| 微信读书中的书籍、划线和笔记 | weread-skills（微信读书技能） | 用户需要原书以外的事实时，再增加独立来源 |
| 图片型社交媒体内容 | 已授权浏览器会话 + 原图保留 + OCR（光学字符识别） + 目视复核 | 页面文字和图片内容冲突时，以可见原图为证据并记录冲突 |
| 音频或视频内容 | 合法可获取的原始媒体 + ASR（自动语音识别） + 时间码 + 必要的关键帧 | 专有名词、数字或画面会改变结论时，回到原始媒体复核 |
| 多份长文档的综合问答 | 本地可搜索语料或 NotebookLM（笔记本语言模型） | 关键结论需要精确引用时，回到原文定位 |
| B 站或 YouTube 单条/批量视频 | `video-source-capture`（视频源采集） | 已有字幕不能支撑结论时下载音频并运行 ASR（自动语音识别） |
| X 或小红书帖子、图文和视频 | `social-source-capture`（社交平台采集） | 需要登录、验证码或会话刷新时，由用户先完成授权验证 |
| Reddit 市场调研、用户问题和社区讨论 | `reddit-source-capture`（Reddit 信息采集） | 持续批量或商业用途切换到正式 Data API（数据接口）授权路线 |

## 公开工具的评估顺序

1. 是否能获取当前决策所需的关键信息。
2. 在当前站点规则、账号权限和运行环境下是否稳定可用。
3. 结果是否能回到原始来源复核。

只有工具跑通真实任务后，才把它写入新的站点或任务 Skill（技能）。
