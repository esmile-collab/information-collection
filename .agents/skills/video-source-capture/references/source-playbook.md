# B 站与 YouTube 路线

## B 站

首选 `yt-dlp`，因为当前版本包含单视频、合集、搜索、空间和动态等 Bilibili（哔哩哔哩）提取器。先执行元数据和字幕模式；需要声音时再下载音频。

早期本机案例使用过解析移动页直链的脚本，页面结构变化后已经不适合作为公共入口。只有 `yt-dlp` 当前链接失败且排除权限问题后，才考虑为单个站点补充后备解析器。

## YouTube

1. `yt-dlp --write-subs --write-auto-subs` 同时保存字幕与元数据，并使用本机 Node.js（JavaScript 运行时）处理当前页面挑战。
2. `youtube-transcript-api` 作为补充；当前 IP 的真实测试返回请求限制，不把它当成稳定主路线。
3. 字幕不可用或质量不足时下载音频并运行 ASR（自动语音识别）。
4. 私有列表、年龄限制和账号内容只使用用户授权的浏览器会话。

YouTube 会调整登录和反自动化要求。2026-08-20 的公开链接元数据测试通过，连续字幕测试随后触发“确认不是自动程序”的登录要求。每个链接都先做元数据测试，再决定是否使用 `--cookies-from-browser`。不导出全站 Cookie（会话凭证）到工作区。

## 交付最小集

- `*.info.json`：原始元数据。
- `*.srt` 或 `*.vtt`：站内字幕；没有时提供 ASR 的 TXT/SRT/JSON。
- `source.md`：来源、时间、方法、缺口和核验记录。
- 只有任务需要时保留音频、视频或关键帧。
