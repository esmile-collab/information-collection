# 社交平台采集

## 目标

完整保留用户实际看见的帖子内容和多模态证据，输出可搜索、可回看、可区分作者自述与外部事实的本地产物。

## 输入边界

确认链接或搜索范围、信息用途、是否需要评论区、时间范围和输出目录。默认只采集当前帖子及其直接媒体，不自动扩展作者历史内容、关注关系或评论用户。

只使用公开页面或用户已授权的会话。出现验证码、频率限制或账号风险提示时停止自动操作。

## 执行流程

1. 运行工作区 `scripts/check-source-tools.sh social`。
2. 打开原页面，记录最终 URL（统一资源定位符）、可见作者、发布时间、正文、媒体数量和采集时间。动态加载或登录态内容优先用 Kimi WebBridge（Kimi 浏览器桥）在用户已有会话中确认完整性。
3. 按站点选择路线：
   - X：浏览器保留正文、线程和文章；`gallery-dl` 获取图片与元数据；帖子视频交给 `yt-dlp`。
   - 小红书：优先保存当前可见页面与全部原图；需要批量媒体时使用工作区 `.tools/vendor/XHS-Downloader/`。
4. 对含关键信息的图片运行：

   ```bash
   swift .agents/skills/social-source-capture/scripts/ocr_images.swift IMAGE... > ocr.json
   ```

5. 逐图核对顺序、缺图、裁切和 OCR（光学字符识别）错误。数字、日期、专有名词和结论性句子必须回看原图。
6. 输出来源记录，区分：页面可见事实、作者自述、独立来源核验、分析推断。

## 验证

- 帖子 URL、作者、可见时间、正文和媒体数量与页面一致。
- 图片和视频文件非空；图片尺寸合理；视频用 `ffprobe` 验证。
- 轮播图顺序完整，OCR（光学字符识别）结果能定位回原图。
- X 的外链图片已经本地化；仍是远程 URL（统一资源定位符）时明确标记未完成。
- 小红书日期存在页面时间、分享链接时间和截图时间冲突时，保留三者并说明采用口径。

## 路由与停止条件

- 具体命令、成熟度和已知风控见 [source-playbook.md](references/source-playbook.md)。
- 登录态失效时不循环重试；请用户在浏览器完成验证后继续。
- 页面已完整本地化且关键内容完成目视复核时停止采集。
